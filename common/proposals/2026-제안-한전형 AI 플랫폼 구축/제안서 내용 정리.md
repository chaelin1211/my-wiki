**소제목 1-1. 자연어 SQL 자동 생성 및 사전 검증**
- 사용자가 입력한 자연어를 SQL로 자동 변환
- 발주처 사전 정의 유스케이스에 따른 SQL 생성 및 데이터 호출
- 정형데이터 자연어 검색을 위한 메타데이터 관리
- 다양한 관계형 데이터베이스 호출 지원
- 생성된 SQL의 문법 및 실행 가능 여부 사전 검증

### 대제목 2. 생성 SQL 검증 및 실행 안전성 확보

> **Key Point:** 생성된 SQL의 문법·실행 가능 여부를 사전 검증하고, 사용자 권한과 읽기전용 정책, 쿼리 부하 제어를 통해 안전하게 통제된 데이터 조회 환경을 제공하겠습니다.

**소제목 1. SQL 사전 검증 및 권한 제어**

- 생성된 SQL의 문법 및 실행 가능 여부 사전 검증
- 사용자 권한에 따른 접근 가능 DB·테이블·컬럼 제한

**소제목 2. 안전한 실행 정책**

- SELECT 중심의 읽기전용 정책 기본 적용
- 대량조회·장시간 쿼리·과도한 조인 제한

### 대제목 3. 결과 제공·이력 관리

> **Key Point:** 생성된 SQL·실행결과·오류 이력을 조회하고 조회 결과를 원천 권한과 마스킹을 유지한 채 표·차트·요약으로 제공하겠습니다.

**소제목 3-1. 결과 시각화 및 이력 관리**
- 생성된 SQL·실행결과·오류 이력 조회
- 조회 결과를 표·차트·요약 등으로 제공 (원천데이터 권한·마스킹 유지)


생성 전
❍ 발주처에서 사전 정의한 유스케이스에 따라 SQL 생성 및 데이터를 호출할 수 있어야 함
❍ 정형데이터 자연어 검색을 위한 메타데이터를 관리할 수 있어야 함

생성 
❍ 사용자가 입력한 자연어를 SQL로 자동 변환할 수 있어야 함

검증
❍ 사용자 권한에 따라 접근 가능한 DB, 테이블 및 컬럼을 제한할 수 있어야 함 
❍ SELECT 중심의 읽기전용 정책을 기본으로 하여야 함 
❍ 생성된 SQL의 문법 및 실행 가능 여부를 사전 검증할 수 있어야 함
❍ 대량조회, 장시간 쿼리, 과도한 조인을 제한할 수 있어야 함

ast 파싱
- 쿼리 구조 정적 분석
- 복잡도 분석
	- JOIN, 서브쿼리, 윈도우 함수 등 카운트
메타데이터 비교
 - 참조한 테이블·컬럼이 실제 DB에 존재하는지 → AST에서 테이블·컬럼 노드를 뽑아 메타데이터와 대조
 - 타입 정합성 (숫자 컬럼에 문자 비교 등)

explain
* explain 쿼리로 실행 계획을 파싱하여 Cost, Rows, Scan 유형 확인
실행 비용 계산
* 앞선 비용 확인 단계에서 산출된 점수를 가지고 총 점수 계산
케이스 별 후처리
* 기준 외의 대량 조회, 복잡도 이상 쿼리(과도한 조인, 장시간 유발 쿼리) 제한
	* LIMIT 주입을 통해 일부 데이터만 조회하도록 생성 쿼리 수정

실행
❍ 다양한 관계형 데이터베이스 호출을 지원하여야 함 
❍ 생성된 SQL, 실행결과 및 오류 이력을 조회할 수 있어야 함
❍ 조회 결과를 데이터 특성에 따라 표·차트·요약 등으로 제공하되 원천데이터 권한과 마스킹을 유지해야 함 

쿼리 생성 -> 실행 -> 결과 생성
					- 실패 시, 오류 이력 등록
					- 시각화 (표, 차트)
					- 요약


## Ⅳ.1.2.6. 프롬프트 관리
**A. 프롬프트 생명주기 관리 (생성~배포~버전)**
❍ 프롬프트 생성·배포·변경·삭제할 수 있어야 하며, 서비스, 모델별로 관리할 수 있어야 함 
❍ 프롬프트 변경이력을 관리하고 버전별 조회, 비교 및 이전 버전으로 롤백 할 수 있어야 
❍ 서비스별 표준 프롬프트 템플릿을 제공하고 재사용할 수 있어야 함
- 프롬프트 생성·배포·변경·삭제, 서비스·모델별 관리
- 변경이력 관리, 버전별 조회·비교, 이전 버전 롤백
- 서비스별 표준 프롬프트 템플릿 제공·재사용

**B. 검증 & 승인 (운영 반영 전)**
❍ 운영 반영 전 다양한 입력값으로 프롬프트를 테스트하고 응답 결과를 비교·검증할 수 있어야 함
❍ 프롬프트 변경 전·후 품질, 토큰량, 지연 등을 검증하고 비교할 수 있어야 함
❍ 운영 프롬프트 적용 전 검토 및 승인 절차를 지원하고 승인 이력을 관리할 수 있어야 함
- 다양한 입력값으로 테스트, 응답 결과 비교·검증
- 변경 전·후 품질·토큰량·지연 비교 검증
- 운영 프롬프트 적용 전 검토·승인 절차, 승인 이력 관리

**C. 거버넌스 (권한 & 감사)**
❍ 사용자 및 조직별 프롬프트 조회·수정·배포 권한을 차등 부여할 수 있어야 함 
❍ 프롬프트 생성, 수정, 배포, 호출 이력을 저장하고 감사 기능을 제공해야 함
- 사용자·조직별 조회·수정·배포 권한 차등 부여
- 생성·수정·배포·호출 이력 저장, 감사 기능
