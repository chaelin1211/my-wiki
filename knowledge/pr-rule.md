# PR 작성 규칙

## 제목

커밋 메시지와 같은 형식. 타입 프리픽스 + 한글 요약.

```
fix: 대화 생성·채팅 요청의 시스템 전달 방식 변경
perf: SQL 카드 렌더링 시 불필요한 재계산과 DOM 재작성 제거
```

## 말투

**명사형으로 끝내고 마침표를 찍는다.** "~함.", "~됨.", "~발생.", "~정리.", "~제거."

```markdown
- 그룹 이름은 변경 가능한 표시용 값이라 식별자로 부적절.
- 화면만 막고 있어 API 를 직접 호출하면 통과.
```

"~했습니다", "~한다" 로 풀어쓰지 않는다.

## 본문 구성

### `## 문제`

무엇이 잘못됐고 왜 고쳐야 하는지. 증상만 적지 말고 원인을 밝힌다.
배경이 되는 다른 PR이 있으면 여기서 링크한다.

성능 개선처럼 "문제"라는 표현이 어색하면 `## 요약` 으로 대체한다.

### `## 수정`

한 항목당 한 가지 변경. **굵게 쓴 요지** 뒤에 설명을 붙인다.

```markdown
- **`update_user` 는 그룹이 실제로 바뀔 때만 이동 수행** — 현재 `users.group_id` 와 비교.
- **설정 화면의 'LLM' 섹션 제거** — `LlmConfig`·`LlmType` 삭제. 파운데이션 탭은
  DB 기반 LLM 연결만 다룸.
```

판단이 갈렸던 지점은 고른 이유까지 적는다. 검토했지만 택하지 않은 대안이
있으면 별도 절로 남긴다.

### `## 확인`

무엇을 어떻게 검증했는지. 안 한 것은 적지 않는다.

```markdown
- `tsc --noEmit` — 관련 타입 오류 없음.
- 실제 화면에서 육안 확인.
```

체크박스(`- [x]`)를 쓸 때는 `## Test plan` 으로 쓴다.

### `## 관련` (선택)

함께 머지해야 하는 다른 저장소의 PR을 적는다.

```markdown
백엔드 DnA-Platform-Development-Team/dna-sql-agent#136 과 함께 머지
```

- 검증하지 않은 것을 확인한 것처럼 적기
