# LLM은 프롬프트 템플릿의 모양을 그대로 베낀다

## 현상

출력 형식을 예시·템플릿으로 보여 주면, 모델은 "이 부분을 바꿔라"는 설명보다 **눈에 보이는 모양**을 더 강하게 따라 한다. dna-sql-agent의 후속 질문 링크(`[질문](dna-ask)`)에서 같은 일이 네 번 반복됐다.

| 템플릿 | 모델 출력 |
| --- | --- |
| 실제 예시 3개 (`[생산 설비 현황을 보여줘](dna-ask)`) | 다른 고객사 데이터인데도 예시 문장을 그대로 복제 |
| 꺾쇠 자리표시자 (`[<…완전한 문장>](dna-ask)`) | `<질문>(dna-ask)` 같은 깨진 문법 |
| 중괄호 자리표시자 (`[{…}](dna-ask)`) + "{...}를 바꿔라" | `[{미조치 건수…}](dna-ask)` — 중괄호까지 출력 |
| 설명 글자 (`[후속 질문 문장](dna-ask)`) | "후속 질문 문장"을 그대로 출력 |

"하지 마라" 예시에 들어 있는 모양도 똑같이 강화된다. 잘못된 예시 `[{질문}](dna-ask)`가 오히려 중괄호 사용을 부추겼다. 같은 맥락에서 HTML을 쓰지 말라는 규칙이 없으면 모델은 강조하려고 `<font color="red">`를 쓰고, 마크다운 렌더러는 이를 글자 그대로 보여 준다.

## 사례: 도구 호출 문장 예시가 실제 도구 호출로 (2026-10-21)

시스템 프롬프트와 도구 설명에 `describe_schema(group="cluster name")`, `describe_schema(["A.T1", "A.T2"])` 같은 **파이썬 호출 문장 예시**를 두었더니, Gemma 4(vLLM)가 자기 고유의 도구 호출 형식 대신 이 문장을 그대로 출력했다. 해석기는 문장 전체를 도구 이름으로 넘겨 `Tool 'describe_schema(search="작전")<tool_call|>' not found`가 났다. 예시를 "`describe_schema` with `group` set to the cluster name"처럼 설명형으로 바꾸자 같은 요청이 정상 형식으로 호출됐다. 깨진 호출이 대화 기록에 남으면 모델은 그 형식을 계속 따라 한다. → [[projects/dna-sql-agent/issues/describe-schema-tool-call-syntax-in-name]]

## 대응

- 템플릿에는 **베껴도 안전한 모양만** 둔다. 자리표시자 기호(`{ }`, `< >`)를 쓰지 않고, 무엇을 넣을지는 말로 설명한다.
- 금지 예시는 금지할 요소 **하나만** 틀리게 쓰고, 나머지는 올바른 모양을 유지한다.
- 모양이 중요하면 프롬프트만 믿지 말고 **출력 후처리**(응답 정리 미들웨어 등)로 보정한다. 프롬프트 수정은 매번 새로운 버릇을 만들 수 있다.
- 렌더러가 해석하지 않는 형식(HTML 등)은 "쓰지 말 것"을 명시한다.
- 도구 설명·시스템 프롬프트에는 호출 문장 모양(`tool(arg="…")`)을 쓰지 않는다. 인자는 이름과 뜻을 말로 설명한다.

## 화면 보정 적용 (2026-10-19)

프롬프트를 다듬은 뒤에도 저장된 답변 1,821건 중 형식 위반이 9월 2.0%, 10월 0.9% 남았다. 남은 위반은 모양이 정해져 있어서, 렌더 직전에 `dna-ask`가 든 줄만 정규식으로 고쳤다.

| 남은 위반 | 렌더 결과 | 보정 |
| --- | --- | --- |
| `[질문] (dna-ask)` | 글자 그대로 노출 | 공백 제거 |
| `[질문](dna-ask` | 글자 그대로 노출 | 괄호 닫기 |
| 리스트 기호 없이 `[질문](dna-ask)` | 버튼이 한 줄로 붙음 | 앞에 `- ` 추가 |

굵게(`**[..](dna-ask)**`)·번호 목록은 렌더러가 정상 처리해서 보정 대상이 아니었다. 렌더 시점에 고치면 이미 저장된 예전 대화도 함께 고쳐진다. → [[projects/dna-sql-agent/decisions/050-dna-ask-link-render-normalization]]
