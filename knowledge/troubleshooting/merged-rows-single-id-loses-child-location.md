# 여러 저장 행을 한 화면 항목으로 합치면 id 하나로는 하위 항목 위치를 못 가리킨다

## 문제 패턴

서버는 한 단위(예: 채팅 답변)를 여러 행으로 나눠 저장하고, 하위 항목(차트·첨부 등)을 그중 특정 행에 붙인다. 화면은 이 행들을 한 항목으로 합쳐 보여 주면서 id를 하나만 남긴다(보통 첫 행). 이후 하위 항목에 대한 동작(북마크·삭제·수정)을 "항목 id + 하위 항목 id"로 요청하면, 서버가 그 행에서 하위 항목을 찾지 못해 404가 난다.

## 알아채기 어려운 이유

- 하위 항목이 우연히 대표 행에 있으면 정상 동작한다. 저장 분배 방식이 바뀌거나 대표 행이 달라지는 순간부터 실패한다.
- 실시간 흐름과 새로고침 흐름이 서로 다른 id를 쓰면 한쪽에서만 재현된다.
- "응답에 id가 오는데 왜 안 되지"로 보이기 쉽다. 그 id는 단위당 하나라 하위 항목 위치를 담을 수 없다.

## 해결 패턴

- **클라이언트:** 합치기 전에 하위 항목마다 원래 행 id를 붙여 두고(`sourceRowId`), 하위 항목 동작에는 그 값을 쓴다. 표시·그룹핑용 id와 실제 저장 id를 분리한다.
- **서버:** 요청한 행에 없으면 같은 상위 범위(예: 같은 대화) 안에서 하위 항목의 고유 id로 실제 행을 찾아 보정한다. 권한은 요청 행으로 먼저 확인하고 그 범위 안에서만 찾는다.
- 저장된 id로 나중에 다시 읽는 경로(목록·대시보드)가 있으면 저장 시점에 실제 행 id로 맞춘다.
- 실시간 흐름처럼 클라이언트가 행 id를 모르는 경로가 있으면 서버 보정이 필요하다.
