# PostgreSQL JSONB는 객체 키 순서를 보존하지 않는다

## 증상

JSON 객체를 JSONB 컬럼에 저장했다가 다시 읽으면 키 순서가 바뀐다. 키 순서로 화면 컬럼·필드 순서를 정하는 코드에서 "실시간 화면은 정상인데 다시 불러오면 순서가 다르다"로 나타난다.

```
저장: {"위치명": …, "최대수량": …, "현재재고": …, "여유공간": …}
조회: {"위치명": …, "여유공간": …, "최대수량": …, "현재재고": …}
```

## 원인

JSONB는 객체를 정규화해서 저장한다. 키를 **바이트 길이가 짧은 순 → 같은 길이면 바이트값 순**으로 정렬하고, 중복 키는 마지막 값만 남긴다. `json` 타입은 입력 텍스트를 그대로 보관하므로 순서가 유지된다.

영문 컬럼명은 길이순이 우연히 원래 순서와 맞는 경우가 많아 잘 드러나지 않는다. 한글은 한 글자가 UTF-8 3바이트라 글자 수 차이가 바로 순서 차이가 된다.

## 해결

- 순서가 의미 있으면 **배열로 따로 저장**하고 그 배열을 기준으로 쓴다(예: `columns: ["위치명", "최대수량", …]` + `rows`). 배열은 JSONB에서도 순서가 유지된다.
- 원문 그대로가 필요하면 `json` 타입을 쓴다(인덱스·연산자 제약 있음).
- 프론트에서 `Object.keys(obj)` 순서에 기대는 코드를 점검한다. 엑셀 내보내기(`XLSX.utils.json_to_sheet(rows, { header })`)도 같은 문제가 있다.
