# 멀티 워커 설정 전파 — 신호는 "적용" 시점에만, 신호 종류는 목적별로

## 문제

설정을 "저장 → 적용" 2단계로 운영하면서, 워커(프로세스)마다 메모리에 올린 설정을 공유 신호 파일로
따라잡게 할 때 흔히 꼬이는 지점.

- **저장 시점에 신호를 쓰면** 다른 워커가 따라잡으며 파일의 현재 저장값을 읽어 들인다 → 저장 = 적용이 된다
- **"자기 미적용 표식이 있으면 따라잡기"** 같은 조건도 같은 결과를 낸다
- **캐시 무효화 같은 다른 목적에 같은 신호를 쓰면**, 그 신호를 받은 워커가 저장만 해둔 설정까지 적용한다
- **미적용 표식을 워커 메모리에 두면** 어느 워커가 응답하느냐에 따라 "적용 필요" 배너가 보였다 안 보였다 한다

## 패턴

| 신호/표식 | 쓰는 시점 | 읽는 쪽 동작 |
|---|---|---|
| 리로드 스탬프 | **적용(apply)** 때만 | 스탬프 > 이 워커의 마지막 적용 시각이면 재적용 |
| 목적별 캐시 스탬프 | 해당 캐시를 바꾸는 API | 그 캐시만 비움 (재적용 없음) |
| 미적용 표식 | 저장 때 | 공유 위치(파일·DB)에 기록, 적용 때 삭제 |

- 따라잡기는 요청 처리 **전** 미들웨어에서 → 적용 이후 어느 워커의 요청도 새 설정으로 처리
- 적용한 워커는 "스탬프 쓰기 → 마지막 적용 시각 갱신" 순서로 자기 신호에 반응하지 않게
- 기동 전 스탬프는 반영된 것으로 본다(새 프로세스는 현재 설정을 로드함)

## 한계

- 요청이 없는 워커는 다음 요청까지 이전 설정. 실행 중인 작업은 시작 시점 설정으로 끝남
- 신호 파일은 설정 디렉터리 공유 전제 — 컨테이너 여러 개면 공유 볼륨 필요
