# "비어 있음"을 신호로 쓰지 않기 — 추론하지 말고 기록한다

## 문제

"아직 설정하지 않음"과 "일부러 비웠음"은 저장소에서 **똑같이 비어 보인다.**
그래서 빈 상태를 신호로 삼는 코드는 두 의도를 구분하지 못한다.

한 시스템에서 같은 함정을 세 곳에서 만났다.

| 빈 상태 | 겹친 두 의도 | 잘못된 동작 |
|---|---|---|
| 권한 목록 `[]` | 제한 없음 / 전부 해제 | 관리자가 전부 해제하니 **전원 허용**이 됨 |
| 테이블에 행 0건 | 신규 설치 / 전부 삭제 | 기동할 때마다 기본값이 되살아나 **관리자 조정이 원복** |
| `max(created_at)` 없음 | 변경 없음 / 행이 전부 삭제됨 | 변경을 **감지 못 함** |

특히 위험한 건 **의미가 뒤집히는** 경우다. 권한에서 "미설정이니 허용"이라는
관대한 기준이 "전부 해제"에도 그대로 적용되면 잠그려던 것이 열린다.

## 패턴

**추론하지 말고 사실을 기록한다.** 빈 상태에서 의도를 역산하려 하지 말고,
그 일이 일어났다는 것 자체를 별도로 남긴다.

```python
# ✗ 추론 — 비었으니 아직 안 했겠지
if await count_rows() == 0:
    await seed_defaults()

# ✓ 기록 — 했으면 표식을 지운다
if config[name].get("pending_seed"):
    await seed_defaults(name)
    config[name].pop("pending_seed")
    save(config)
```

기록을 어디에 둘지는 수명에 맞춘다.

| 기록 | 어디 | 이유 |
|---|---|---|
| 일회성 시딩 완료 | 설정 파일·전용 테이블 | 재기동해도 남아야 함 |
| "적용 안 된 변경이 있음" | 프로세스 메모리 | 재기동하면 어차피 반영되므로 초기화가 맞음 |

## 판별 기준

빈 상태로 분기하는 코드를 보면 이렇게 물어본다.

1. **누군가 일부러 비울 수 있나?** 비울 수 있으면 그 의도와 "미설정"이 반드시 겹친다.
2. **겹쳤을 때 어느 쪽으로 틀리나?** 보안·권한이면 관대한 쪽으로 틀리는 게 최악이다.
3. **비운 사건을 기록할 자리가 있나?** 없으면 만든다. 타임스탬프는 답이 아니다 —
   행을 전부 지우면 타임스탬프도 같이 사라진다.

## 곁가지 — 기준 시각도 같은 함정

"마지막으로 적용한 시각"을 모듈 import 시점에 잡으면, 기동 중에 일어나는 쓰기가
그보다 늦어 미반영으로 잡힌다. 기준 시각은 **그 상태가 참이 되는 시점**에 찍어야 한다.
기동이라면 모듈을 읽은 때가 아니라 초기화가 끝난 때다.
