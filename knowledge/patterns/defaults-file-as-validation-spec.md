# 기본값 파일을 검증 스펙으로 겸용하기 — 사이드카 메타 키

## 문제

사용자가 고칠 수 있는 설정 파일(`config/*.json`)이 잘못돼도 앱은 대개 그냥 뜬다.
키가 빠지면 기본값으로 넘어가고, 타입이 틀리면 한참 뒤 엉뚱한 곳에서 터진다.

검증을 붙이려고 스키마 파일을 따로 만들면 **기본값 파일과 스키마 파일 두 벌**이
된다. 필드를 추가할 때 양쪽을 고쳐야 하고, 한쪽만 고치면 조용히 갈라진다.
설정 관리에서 가장 자주 데이는 실패가 정확히 이것이다.

## 패턴

**기본값 파일 자체를 스펙으로 쓴다.** 값에서 타입과 필수 여부를 읽고, 값만으로
표현할 수 없는 것만 `_` 접두 메타 키로 적는다.

```jsonc
{
  "temperature": 0.7,              // number, 필수 — 표기 불필요
  "max_tokens": null,              // 값으로 타입 추정 불가
  "_max_tokens": { "_type": "number", "_required": false },

  "allow_origins": ["http://localhost:3000"],
  "_allow_origins": { "_item": "" }   // 문자열 배열
}
```

| 메타 | 뜻 |
|---|---|
| `_required` | 기본 `true`. `false` 면 설정 파일에 없어도 통과 |
| `_type` | 값 대신 타입 지정 (기본값이 `null` 일 때) |
| `_item` | 배열 원소 템플릿 (객체면 원소 한 벌을 그대로 적는다) |

메타는 **형제 위치의 `_키` 사이드카**에 둔다. 값 자체를 건드리지 않아 스칼라·배열·
객체 어디에나 같은 방식으로 붙는다. 로드할 때 `_` 키를 재귀적으로 걷어내면 순수한
기본값이 나오므로, API 응답이나 새로 생성되는 설정 파일에는 메타가 섞이지 않는다.

## 판정 규칙

- **없는 키 / 타입 불일치 → 기동 중단.** 파일 경로·키 경로·기대/실제를 함께 낸다
- **모르는 키 → 경고만.** 구버전 잔재로 기동을 막을 이유는 없다
  (단, 값이 서드파티 생성자 인자로 그대로 넘어가는 섹션은 예외 — 모르는 키가
  런타임 `TypeError` 가 되므로 화이트리스트로 막는다)
- **배열은 `_item` 을 준 것만 원소를 검사.** 첫 원소로 타입을 추정하면 혼합 배열에서
  거짓 실패가 난다
- **`_required: false` 는 그 키 하나에만 적용.** 배열에 주면 "배열이 없어도 된다"는
  뜻이지 "원소 필드가 선택"이라는 뜻이 아니다

## 검증기 자신의 사각지대

이 패턴의 함정은 **스펙이 잘못 쓰여도 아무도 모른다**는 것이다. 짝 없는 사이드카
(`_ghost`), 값과 어긋난 `_type`, `_item` 빠진 배열, 오타 난 메타 키(`required` vs
`_required`) — 전부 검사를 조용히 헐겁게 만들 뿐 에러가 아니다.

그래서 **스펙용 린터를 따로 둔다.** 기본값 파일을 훑어서 위 항목을 잡고, 메타를
벗긴 기본값이 자기 스펙을 통과하는지(라운드트립)까지 확인한다. 규칙 위반은 ERROR,
검사가 느슨해지는 지점(`_item` 없는 배열)은 WARN 으로 나눠 `--strict` 로 승격 가능하게
한다. 이 린터는 개발·CI 전용이라 배포 산출물에서는 빼도 된다.

## 적용 예

- dna-sql-agent: `src/dna/settings/defaults/*.json` + `settings/validation.py`
  (기동 검증) + `scripts/check_default_config.py` (스펙 린터)
  → [[projects/dna-sql-agent/decisions/034-defaults-as-config-validation-spec]]

## 언제 안 맞는가

- 설정 항목이 많아 메타 표기가 값보다 많아지면 JSON Schema 쪽이 낫다
- enum·범위·정규식 같은 제약이 필요하면 이 방식으로는 부족하다. 그건 별도 스키마
  (Pydantic 등)가 API 입력을 검증하는 층에서 맡고, 이 패턴은 "파일이 직접 수정되는
  경로"의 최소 방어선으로 쓴다
