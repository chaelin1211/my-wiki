# 새 권한 항목은 "행이 없으면 넣기"가 아니라 표식으로 한 번만 부여한다

## 문제

권한을 "행이 있으면 허용, 없으면 거부"로 저장하는 시스템에 새 권한 항목을 추가하면, 이미 운영 중인 환경에는 그 항목의 행이 하나도 없다. 그대로 배포하면 **모두가 갑자기 거부**된다. dna-sql-agent에서 "결과 화면" 항목을 추가했을 때, 그대로 두면 모든 사용자가 표·차트를 못 볼 상황이었다.

## 하면 안 되는 방법

**기동할 때마다 "행이 없으면 기본 권한을 넣는다"**로 처리하는 방법입니다. 관리자가 일부러 모든 그룹에서 권한을 해제하면 행이 0개가 되는데, 다음 재시작 때 기본 권한이 되살아납니다. 이 방식은 "아직 한 번도 설정하지 않음"과 "관리자가 전부 해제함"을 구분하지 못합니다.

## 방법

1. **표식 남기기:** 기본값 파일에 새로 생긴 항목을 운영 설정에 추가하면서 `pending_permission_seed: true` 표식을 남깁니다. 운영 설정을 기본값과 합쳐 읽지 않는 구조라면, 이 단계가 새 항목을 운영 설정에 넣는 유일한 경로이기도 합니다.
2. **한 번 부여:** 기동 시 표식이 있는 항목만 기본 권한을 부여합니다(예: `default_access: true`면 기존 전 그룹).
3. **표식 지우기:** 부여에 **성공한 뒤에만** 표식을 지웁니다. DB 오류가 나면 표식을 남겨 다음 기동 때 다시 시도합니다.
4. **추가만 하기:** 권한은 추가만 하고 지우지 않습니다. 관리자가 이미 조정한 다른 항목은 건드리지 않습니다.

새로 만드는 그룹은 이 장치와 별개로, 그룹을 만들 때 `default_access` 항목만큼 권한을 줍니다.

## 짝: 항목을 없앨 때

쓰지 않게 된 항목은 목록(`RETIRED_UI_FEATURES`)에 올려 두고, 기동 시 운영 설정과 DB 권한에서 지웁니다. 지울 게 없으면 아무 일도 하지 않으므로 여러 번 실행해도 결과가 같습니다.

## 테스트로 고정할 것

- 표식이 있는 항목만 부여되는지
- 두 번 기동해도 한 번만 부여되는지
- DB 오류가 나면 표식이 남는지
- 새 그룹에는 기본 허용 항목만 더해지고, 이미 있는 그룹은 그대로인지
