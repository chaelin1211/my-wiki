# 2026-10-12 — 도구 표시명 일원화·지도 행정구역 갱신·위젯 새로고침 실패 처리

> 10-08 오후에 시작해 10-12에 마무리한 개선 작업 묶음. 백엔드 #176, 웹 #101 (브랜치 `feat/tool-display-name`).

## 목표

- 채팅 카드는 한글 도구명, 관리자 도구 접근 제어는 영어 클래스명이라 어긋나는 것을 맞춘다. 표시명은 한 곳에서만 관리한다.
- 지도 choropleth에서 `전남광주통합특별시` 데이터가 표시되지 않는 문제를 해결한다.
- 대시보드 위젯 새로고침이 DB 변경 등으로 실패해도 아무 표시가 없는 문제를 해결한다.

## 수행한 작업

1. **도구 표시명 일원화**
   - `src/dna/tools/display_names.py` 에 `ToolDisplayName` enum을 둔다. 키는 `tool_access.json` 의 설정 키(클래스명), 값은 한글 표시명이다.
   - `dadap` 의 `agent.py` 에 있던 `TOOL_DISPLAY_NAMES`(키가 도구 이름 `run_sql`)를 지우고, 에이전트 생성 시 `tool_display_name_resolver` 를 주입받게 했다. `agent_service.py` 가 도구 이름 → 클래스명 → enum 순으로 찾는다.
   - 관리자용 `GET /api/v1/settings/tool-display-names` 를 추가하고, 웹 관리자 도구 표에 한글명 + 작은 클래스명을 표시한다.
   - 새로 붙인 표시명: `질문 의도 분석`(ExtractRequirements), `지표 매핑`(PlanMetrics), `도구 사용 사례 저장`·`도구 사용 사례 검색`(agent memory), `텍스트 메모리 저장`. 처음 붙인 "질문 사례 저장"은 실제 역할(성공한 도구 호출 저장)과 달라 교체했다.
2. **지도 행정구역 갱신**
   - `kr_sido.geojson` 에 `전남광주통합특별시` 지역을 추가했다. 폴리곤은 전라남도 폴리곤에서 광주 자리 구멍만 메운 모양이다. 기존 17개 지역은 그대로다.
   - 별칭 `전남광주특별시` 를 추가했다.
3. **대시보드 위젯 새로고침 실패 처리**
   - 백엔드 `render_bookmark`: 실패를 `CONNECTION_FAILED`(503) / `QUERY_FAILED`(422) / `CHART_MISMATCH`(422)로 구분해 `{"detail": {"code", "message"}}` 로 응답한다. DB 원문 오류는 로그에만 남긴다. 결과 0건은 204 대신 200 + `empty: true` 로 응답한다.
   - 웹: 실패하면 새로고침 아이콘 툴팁을 `!` 로 열어 두고, 마우스를 올리면 "새로고침 실패: 이유"를 보여준다. 실패한 위젯 테두리를 2초 강조하고, 전체 새로고침 후 실패 개수를 토스트로 알린다. 결과 0건이면 기존 차트를 유지한다.
   - 공용 툴팁에 꼬리 색 옵션 `arrowClassName` 을 추가했다.
4. 10-08 업무기록 등록·확정 (timesheet 스킬).

## 핵심 결정

- **도구 표시명은 설정이 아니라 `dna` 쪽 고정 enum으로 둔다.** 설정 파일은 서버마다 복사본이 생기고 운영자가 바꾸는 항목이라 맞지 않는다. 도구 클래스 속성은 프레임워크(`dadap`)에 서비스 문구가 들어가서 맞지 않는다.
  → ADR: [[decisions/047-tool-display-name-fixed-enum]]
- **통합 행정구역은 기존 경계에 새 폴리곤을 추가해 공존시킨다.** 경계 파일을 통째로 새 기준으로 바꾸면 통합 전 데이터(광주·전남 따로)를 그릴 수 없다. 별칭으로 `전라남도` 에 붙이면 광주 자리가 구멍으로 남는다(전남 폴리곤이 광주 자리를 비워 둔 도넛 모양).
- **실패 문구는 백엔드가 이유만, 웹이 "새로고침 실패:" 이름표를 붙인다.** 표기를 바꿀 때 웹만 고치면 되도록 나눴다.
- **실패 표시는 화면에만 둔다.** DB 컬럼 추가 없이 시작하고, 페이지를 다시 열면 사라지는 한계는 감수한다.

## 배운 것

- Radix 툴팁을 강제로 열어 두면 hover 감지, 자기 닫힘, 가장자리 깜빡임 문제가 차례로 생긴다. → [[knowledge/troubleshooting/radix-tooltip-forced-open-hover]]
- `mocker.patch.dict(sys.modules, ...)` 는 테스트가 끝날 때 그동안 새로 import된 모듈까지 지운다. 다음 테스트에서 모듈이 두 벌이 되어 패치가 엉뚱한 쪽에 걸린다. → [[knowledge/troubleshooting/patch-dict-sys-modules-drops-new-imports]]
- 시각화 도구는 지정한 컬럼이 없으면 오류 대신 자동 차트로 대신 그린다. 그래서 컬럼이 바뀐 위젯은 대부분 `CHART_MISMATCH` 가 아니라 200으로 끝나고, 모양이 바뀐 차트가 그려진다.
- 지도 매칭은 경계 파일 이름·옛 통계 코드·별칭 표와 글자 그대로 비교한다. 영문명(`Seoul`)은 경계 파일에 있지만 비교 대상이 아니고, 행정표준코드는 옛 코드와 겹쳐 `26` 이 울산으로 잘못 매칭된다(미수정).

## 문제 & 해결

- **문제:** 위젯 새로고침이 실패해도 예전 차트·예전 갱신 시각이 그대로 남아 실패 여부를 알 수 없음.
- **원인:** 웹이 `catch {}` 로 오류를 버리고, 백엔드는 사용자 데이터 변경도 500으로 돌려줌.
- **해결:** 실패 원인 구분 응답 + 툴팁·강조 표시.
  → 이슈 로그: [[issues/log]]
- **문제:** 새로고침 툴팁이 마우스를 올려도 `!` 가 안 사라지거나, 깜빡이며 사라짐.
- **해결:** 툴팁 열림을 버튼 hover·focus와 `!` 표시 여부로만 정하고, 툴팁에 `pointer-events-none`.
  → [[knowledge/troubleshooting/radix-tooltip-forced-open-hover]]
