# 2026-08-20 — 차트 다중 시리즈 + 엔진별 지원 타입 정리

## 목표

시각화 툴에 combo(이중 축)를 추가하는 중, 엔진마다 지원 차트 타입이 다른데 도구 설명은 하나라서 생기는 문제를 정리한다. 특히 combo 를 지원하지 않는 엔진에 `y` 가 쉼표로 여러 개 올 때 나던 오류를 없앤다.

## 수행한 작업

1. **다중 시리즈를 `y` 의 쉼표 목록으로 표현** — 새 차트 타입을 만들지 않고 기존 `bar`/`line`/`area` 등에 얹음. 컬럼 해석을 `dna/integrations/chart_columns.py` 의 `resolve_columns()` 하나로 모아 echarts·devextreme·plotly 세 생성기가 공유.
2. **devextreme 노출 목록 보완** — 생성기의 `_map_series_type()` 은 처음부터 `area`/`stackedBar`/`stackedArea`/`spline` 을 매핑했는데 `CHART_TYPES_BY_ENGINE` 에 없어 LLM 이 고를 수 없던 상태. 목록만 추가.
3. **쉼표 목록이 렌더러까지 새던 버그 수정** — `bar`/`line` 외 분기(기본값 `auto`, scatter, pie, histogram, heatmap)가 `"A,B"` 를 컬럼명으로 그대로 넘겨 예외. 해석을 함수 상단으로 올려 다중 시리즈 분기만 전체 목록을 쓰고 나머지는 첫 컬럼만 사용. echarts 의 pie/scatter/heatmap 도 동일하게 보완.
4. **도구 설명을 엔진 지원 타입으로 조립** — 차트 타입별 축 용법을 `CHART_TYPE_AXIS_HINTS` 에 데이터로 두고 현재 엔진 목록으로 걸러 `x`/`y`/`value`/`color` 설명을 생성. 같은 문구를 쓰는 타입은 `bar/line/area: numeric` 처럼 렌더링 단계에서 합침.
5. **지원 밖 타입은 오류로 반환** — `chart_type` 의 `Literal` 검증을 걷고 `enum` 만 스키마에 남김. 도구가 임의로 대체하지 않고 사유와 사용 가능한 타입을 돌려줌.
6. **plotly `combo` 추가** — `y` 는 주 y축 막대, `value` 는 보조 y축 선. `go.Bar` + `go.Scatter(yaxis="y2")`.
7. **웹 UI 정리** — 드롭다운 focus 시 글자·아이콘 색 고정, 항목 4종 반응 통일, 모서리 6px. 다크모드 `--popover` 가 `--background` 보다 어두워 떠 보이지 않던 것 수정.
8. **문서 정리** — 웹의 `docs/dual-axis-chart-design.md` 를 현행 기준으로 다시 쓰고 `combo-chart-design.md` 로 이름 변경. 웹 `CLAUDE.md` 에 PR 양식 절 추가(백엔드와 동일화).

## 핵심 결정

- **엔진별 능력 차이를 도구 스키마 조립에서 흡수한다.** 지원하지 않는 타입은 설명·파라미터 어디에도 내보내지 않고, 그럼에도 요청되면 사유와 선택지를 담은 오류를 반환한다. 도구가 근사 타입으로 대신 그리지 않는다.
  → ADR: [[decisions/037-engine-capability-gating-in-tool-schema]]

- **이중 축은 별도 타입(`combo`)으로 두고, 인자로 차트 형태를 바꾸지 않는다.** `bar` + `value` 로 이중 축을 내던 구현은 되돌렸다.
  → ADR: [[decisions/038-chart-shape-by-type-not-by-argument]]

## 배운 것

- **LLM 은 스키마에 적힌 것만 안다.** 구현해 놓고 설명에 적지 않으면 모델은 "지원되지 않는다"고 단정한다. 이번 세션에 같은 일이 세 번 반복됐다 — combo 미지원 주장, 이중 축 미지원 주장, 모두-막대+우측 눈금 미지원 주장. 셋 다 기능은 있는데 스키마에 없었다.
- **도구가 실패를 대신 처리하면 사용자 화면이 지저분해진다.** 지원 밖 타입을 근사 차트로 대체했더니 LLM 이 그 안내 문구를 실패로 읽고 재생성해, 사용자에게 같은 시각화가 3개 떴다.
- **`Literal` 은 방어가 아니라 실패다.** pydantic 원본 오류는 LLM 이 고치기 어렵고 맹목적 재시도를 부른다. `enum` 으로 유도하고 런타임에 사유를 담아 돌려주는 편이 한 턴에 복구된다.
- 완전 강제는 provider 의 strict function calling(제약 디코딩)으로만 가능하며, 전 프로퍼티 `required` 등 스키마 제약이 커서 `src/vanna` 공용 어댑터를 건드려야 한다. 이번 범위 밖.

## 문제 & 해결

- **문제:** 기능을 구현했는데 LLM 이 "시각화 도구의 기술적 한계로 지원되지 않습니다"라고 답하고 시도조차 하지 않음.
- **원인:** 도구 설명·파라미터 설명에 그 기능이 없음. 모델은 스키마 밖의 능력을 알 방법이 없어 없는 것으로 단정.
- **해결:** 구현과 설명을 함께 움직이도록 테스트로 고정 — 지원 엔진에는 설명이 반드시 있고, 미지원 엔진에는 절대 없으며, 목록에 올린 엔진은 실제로 렌더해야 통과.
  → 이슈: [[issues/llm-denies-capability-missing-from-tool-schema]]

- **문제:** `y='A,B'` 가 렌더러까지 전달돼 `Value of 'y' is not the name of a column` 예외.
- **원인:** 다중 y 를 절반만 구현. 보내는 쪽은 원본을 넘기도록 바꿨는데 받는 쪽은 `bar`/`line` 두 분기만 고침.
- **해결:** 해석을 함수 상단에서 한 번 하고 분기별로 전체 목록/첫 컬럼을 나눠 씀. 타입별 파라미터라이즈 테스트로 고정.
