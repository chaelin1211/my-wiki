# ADR-049: 가입 경로·승인 기록은 users 칼럼에, 가입일은 승인 시각 기준

## 맥락

회원가입 승인 방식(`auth.signup_approval_required`)을 넣은 뒤, 관리자가 "언제 누가 승인·거절했는지"와 "승인 없이 자동 가입된 계정"을 구분할 방법이 없었다. 상태(`status`)만 바뀌고 처리 시각·처리자가 남지 않았다.

또 화면의 "가입일"은 가입 신청 시각(`created_at`)이라, 승인 방식에서는 실제로 회원이 된 시점과 달랐다. 승인 대기·거절 계정도 가입일이 표시됐다.

## 선택지

### 옵션 A: 가입 심사 이력 테이블 신설 (요청마다 한 줄)
- **장점:** 거절 후 재승인 같은 여러 번의 처리 이력을 모두 보존.
- **단점:** 테이블·조회가 늘고, 현재 요구(마지막 처리 결과·시각)에 비해 과함.

### 옵션 B: `users` 에 칼럼 추가 (마지막 처리만 보존)
- **장점:** 단순. 기존 상태 변경 경로 두 곳에 붙이기 쉬움.
- **단점:** 거절했다가 승인하면 마지막 결과로 덮어씀.

## 결정

**옵션 B를 선택한다.**

- `users.signup_type`: 가입 시점의 승인 설정에 따라 `approval` / `auto` (기존 계정은 NULL, 기존 승인 대기·거절은 `approval` 로 채움).
- `users.review_result`(approved/rejected), `reviewed_at`, `reviewed_by`: 승인 대기·거절 → 활성·거절로 바뀔 때만 기록. 단건 수정·일괄 상태 변경이 같은 SQL(`_UPDATE_STATUS_SQL`)을 써서 빠짐없이 기록된다. 활성↔비활성 변경은 기록을 건드리지 않는다.
- **가입일(`joined_at`, 계산값):** 승인 대기·거절이면 없음, 승인 이력이 있으면 `reviewed_at`, 그 밖에는(자동 가입·기존 계정) `created_at`. 사용자 목록·상세·내 정보 API가 함께 내려 주고, 목록 "최신 가입순"도 이 값(없으면 `created_at`)으로 정렬.

## 근거

- 운영에서 필요한 것은 "지금 이 계정이 언제 승인됐나"이지 전체 심사 이력이 아니다.
- 상태 변경 지점이 두 곳뿐이라 SQL 하나로 기록 누락을 막을 수 있다.
- 자동 가입은 생성 순간이 곧 가입이므로 별도 시각이 필요 없다.

## 결과

- 이 기능 이전에 승인된 계정은 `reviewed_at` 이 없어 가입일이 `created_at` 으로 남는다.
- 거절 후 재승인 시 이전 거절 기록은 사라진다(필요해지면 옵션 A로 확장).
- 승인 대기·거절 계정은 사용자 목록 가입일 칸에 [거절]·[승인] 버튼, 정보 팝업은 "신청일" 표시.
- 가입 신청 목록 API(`GET /admin/signup-requests`)는 남겨 두었으나 화면은 카드 → 사용자 목록 필터 방식으로 확정.
