# ADR-050: 후속 질문 링크 형식은 화면에서 렌더 직전에 보정

## 맥락

답변 끝의 후속 질문 `- [질문](dna-ask)`은 정확한 마크다운 링크일 때만 버튼이 된다(`AskAnchor`가 `href === 'dna-ask'`만 변환). 저장된 답변 1,821건을 분석하니 형식 위반이 9월 2.0%, 10월 0.9% 남아 있었다. 렌더러로 직접 확인한 결과 버튼이 안 되는 형태는 두 가지였다.

- `[질문] (dna-ask)` — `]`와 `(` 사이 공백 → 글자 그대로 노출
- `[질문](dna-ask` — 줄 끝에서 괄호가 닫히지 않음

리스트 기호 없이 쓴 `[질문](dna-ask)`는 버튼은 되지만 여러 질문이 한 줄로 붙었다. 굵게(`**[..](dna-ask)**`)·번호 목록은 정상이었다.

## 선택지

### 옵션 A: 프롬프트 규칙 강화
- **장점:** 원인(모델 출력) 쪽 대응
- **단점:** 이미 "`- ` 필수, href는 정확히 `dna-ask`"로 강하게 써 있음. 모델은 규칙보다 모양을 따라 하는 경향이 있어 효과가 불확실([[knowledge/prompting/llm-copies-template-placeholders]]). 저장된 예전 대화는 그대로 깨진 채로 남음
- **비용/노력:** 낮음, 효과 검증은 어려움

### 옵션 B: 백엔드에서 최종 답변 후처리
- **장점:** 저장 데이터 자체가 정상
- **단점:** 예전 대화는 그대로. 스트리밍 중 화면에는 적용 안 됨
- **비용/노력:** 중간

### 옵션 C: 웹에서 렌더 직전 보정
- **장점:** 스트리밍·최종·예전 대화 모두 적용. DB 원문은 변경하지 않음
- **단점:** 원문과 화면이 달라짐(원문 복사 시 깨진 형태)
- **비용/노력:** 낮음

## 결정

**옵션 C를 선택한다.** `lib/markdown-ask-links.ts`의 `normalizeAskLinks()`를 `MarkdownBubble`에서 `parseFunctionTags` 다음에 한 번 적용한다. `dna-ask`가 든 줄만 대상으로 아래 세 가지를 고친다.

1. `]`와 `(` 사이 공백 제거
2. 줄 끝의 닫히지 않은 `](dna-ask` 괄호 보완
3. 리스트 기호 없이 시작하는 링크 줄에 `- ` 추가

질문 앞뒤의 `{ }`·`< >` 제거는 넣지 않는다(사용자 결정, 버튼 자체는 동작함).

## 근거

형식 위반은 1% 안팎으로 드물고 모양이 정해져 있어, 줄 단위 정규식으로 안전하게 고칠 수 있다. 화면에서 고치면 이미 저장된 대화까지 한 번에 해결되고 프롬프트를 더 복잡하게 만들지 않아도 된다. 스트리밍 도중 덜 온 링크(`](dna-as`)는 건드리지 않도록 해서 괄호가 두 번 붙지 않는다.

## 결과

- 오늘 실제로 깨진 답변을 렌더해 버튼 0→3개, 0→1개 복구 확인. 테스트 `tests/markdown-ask-links.test.mjs`
- 원문 복사(`buildResponseText`)에는 적용하지 않음
- 새로운 형식 위반 모양이 생기면 이 함수에 규칙 추가
- 웹 PR #105
