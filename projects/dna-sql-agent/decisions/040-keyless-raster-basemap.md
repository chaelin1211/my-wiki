# ADR-040: 기본 지도 배경은 키 없는 래스터 타일(Esri 회색 캔버스)

## 맥락

심플 모드(지도 기본 화면)의 기본 타일이던 CARTO 가 무료 사용에 API 키를 요구하기 시작했고, 키 없는 요청에는 타일 이미지 자체에 `API KEY REQUIRED` 워터마크를 인쇄해 내려준다. HTTP 200 이라 에러로도 잡히지 않는다. 제품 코드를 바꾸지 않아도 모든 배포처(dev·linko·mobigen·고객사 설치 패키지)에서 동시에 증상이 나타난다.

CI 워크플로 3개는 `docker run` 에 `-e`·`--env-file`·시크릿 주입이 전혀 없어서, 배포처별로 키를 넣을 통로도 마땅치 않다.

## 선택지

### 옵션 A: CARTO API 키 발급
- **장점:** 화면 모양이 그대로 유지됨. 코드 변경 없이 기존 env(`MAP_TILE_URL_SIMPLE`)에 키 붙인 주소만 넣으면 됨. 월 500만 타일까지 무료.
- **단점:** 공식 안내상 **상업적 사용은 엔터프라이즈 라이선스 논의 대상** — 고객사 납품 제품이라 해당됨. 타일을 사용자 브라우저가 직접 받으므로 **키가 URL 에 노출**되고 그 사용량이 우리 한도에서 차감됨. 폐쇄망 고객사는 어차피 못 씀. 계정·키·한도를 계속 관리해야 함.
- **비용/노력:** 코드 0, 대신 계약·키 관리 상시 부담.

### 옵션 B: OpenFreeMap(OpenMapTiles 벡터 스타일)
- **장점:** 키·요청 한도 없음, 상업적 사용 허용. Positron/Dark 스타일이라 **지금과 거의 같은 모양**. `name:ko` 필드가 있어 한글 지명 가능. 벡터라 고줌에서도 선명. 주간 planet MBTiles 를 받아 폐쇄망 자체 호스팅도 가능.
- **단점:** **벡터 전용**이라 Leaflet 래스터 방식으로는 못 그림 — `maplibre-gl`(gzip 293KB, 현재 leaflet 41KB) + 브리지 도입 필요. 브리지 구조상 드래그가 한 박자 늦음. **WebGL 필수**라 GPU 없는 VDI·구형 PC 에서 위험. 지도 1개당 WebGL 컨텍스트 1개라 대시보드에 지도가 여러 개면 상한(Chrome 약 16개)에 걸림. 서울 z14 한 화면이 약 1.5MB. SLA 없음. `maplibre-gl` 6.x 는 ESM 전용이라 브리지(`require`)와의 호환도 확인 필요.
- **비용/노력:** 신규 의존성 2개 + 벡터 레이어 컴포넌트 + WebGL 폴백.

### 옵션 C: Esri 회색 캔버스 래스터 (World_Light/Dark_Gray_Base + Reference)
- **장점:** 키·계정 불필요. 기존 `TileLayer` 그대로라 신규 의존성 0, WebGL 불필요, 지도 여러 개에도 제약 없음. 심플 모드 취지(데이터가 도드라지는 차분한 배경)에 부합.
- **단점:** 지명이 별도 레이어라 타일 레이어를 한 장 더 그려야 함. 지명이 영문. **지역별로 타일 보유 줌이 다름** — 한국은 밝은 배경 z13, 어두운 배경 z16 까지이고 그 위는 "Map data not yet available" 이미지가 옴. 밝은 배경은 한국에서 z14 이상이 흐릿함.
- **비용/노력:** 코드 약 30줄.

## 결정

**옵션 C를 선택한다.** 기본값은 키 없이 어디서나 뜨는 타일로 두고, 다른 배경을 원하는 배포처는 기존 `MAP_TILE_URL*` env 로 지정한다(키를 붙인 CARTO 주소도 이 통로로 그대로 쓸 수 있다).

## 근거

- 이 제품은 **고객사에 납품**되고 일부는 폐쇄망이다. 제품 기본값이 특정 업체의 계정·키·한도에 묶이면 배포처가 늘어날수록 관리 비용과 라이선스 위험이 함께 는다. 기본값은 "아무 설정 없이도 뜨는 것" 이어야 한다.
- 성능·환경 리스크가 가장 작다. 벡터는 모양과 한글 지명에서 낫지만, **대시보드에 지도 위젯이 여러 개 뜨는 구조**와 **고객사 PC 사양을 모른다는 점**에서 WebGL 컨텍스트 상한과 GPU 부재가 실제 장애로 이어질 수 있다.
- 줌 커버리지 차이는 Leaflet `maxNativeZoom` 으로 흡수된다(밝은 13, 어두운 16). 확대 시 흐려질 뿐 워터마크나 빈 화면은 없다.

## 결과

- 심플 모드에서 지명이 **영문**으로 표시된다. 한글 지명이 요구사항이 되면 옵션 B 를 재검토한다.
- 한국에서 밝은 배경은 z14 이상이 흐릿하다. 데이터를 돋보이게 하는 배경이라는 취지에는 어긋나지 않는다.
- 라벨 타일 레이어가 하나 더 붙어 타일 요청 수가 약 2배가 된다. 요청당 크기가 작아(수 KB~15KB) 영향은 제한적이다.
- env 로 타일을 지정한 배포는 `labelUrl`·`maxNativeZoom` 이 붙지 않는다. **사내 타일에는 지명이 그림에 포함돼 있어야 한다.**
- 출처 문구는 `© Esri | © OpenStreetMap` 로 축약했다. 제공처가 명시한 원문은 `Esri, HERE, Garmin, (c) OpenStreetMap contributors, and the GIS user community` 이며, 분쟁 소지를 줄이려면 원문을 쓰는 편이 안전하다. 우측 하단 모드 토글과 겹치는 UI 제약 때문에 축약을 택했다.
- 재검토 시점: 한글 지명 요구가 생기거나, 고객사 PC 사양이 파악되어 WebGL 을 전제할 수 있게 될 때.
