# ADR-019: 지도 데이터 목록을 from==to 기준으로 분류·그룹핑

## 맥락

지도 좌측 데이터 목록이 케이스마다 의미가 달라 일관성이 없었다. 특히 흐름(flow) 지도는 흐름선과 허브 점이 한 목록에 뒤섞여 보기 불편했고, 한 장비의 시간별 이동(트랙)은 모든 끝점 이름이 같아 라벨이 중복되거나 클릭 시 전부 함께 선택되는 문제가 있었다. 케이스를 3가지로 정리:

- #1 점(분포): lat/lon만
- #2 수치 있는 경로(O-D 흐름): from≠to + value
- #3 수치 없는 이동 경로(한 엔티티 트랙): from===to

## 선택지

### 옵션 A: value 유무로 노출/분류
- **장점:** 초기 직관(수치 없으면 구간 노이즈 제외)
- **단점:** 트랙(#3)과 O-D(#2) 구분이 모호, 같은 장비 경로가 목록에서 빠지는 등 일관성 부족

### 옵션 B: from==to 한 기준으로 분류 + from/id 하위로 라인 접기
- **장점:** 단순·예측 가능. 점과 흐름이 안 섞임(출발 점 헤더 아래 그 출발의 흐름들이 접힘). 트랙은 id로 묶임.
- **단점:** 그룹 렌더 분기(헤더/자식, originPoint) 약간 복잡

## 결정

**옵션 B를 선택한다.** `MapItem`에 `groupKey`(흐름선=from, 점=이름)와 `subLabel`(그룹 내 표시, 예 '→ 부산')을 두고 groupKey로 묶는다.

- `from === to`(#3): id로 묶고 자식은 순번(#i)
- `from !== to`(#2): 출발(from)로 묶고 자식은 `→ 도착 (value)`. 출발 허브 점이 그룹 헤더(클릭 시 그 점 선택). 도착 전용 노드는 단독 행.
- #1 점: 이름(id)로 묶음 — 중복 id는 접기/펼치기(#i)
- 둘 다 value 유무와 무관하게 노출

## 근거

목록의 조직 축은 "출발 노드"가 가장 자연스럽다(흐름은 출발에서 뻗어나가고, 트랙은 단일 엔티티). value 기반 노출 규칙은 #2/#3 경계를 흐려 폐기하고, `from==to` 단일 기준으로 단순화했다.

## 결과

- 흐름선 `featureId`에 끝점 좌표를 포함해 같은 from/to 구간의 중복·동시선택 방지(부수 수정).
- 같은 출발/장비를 선택할 때 이름 기준 라인 전체 강조는 단일 출발(트랙)에선 끔(`singleOriginFlow`).
- 향후: 그룹 자식 라벨에 시간 컬럼 표시(현재 #i) 등은 데이터에 시각 컬럼 있을 때 확장 가능.
