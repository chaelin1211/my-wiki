# ADR-036: 설정 적용 시점을 코드에 선언하고 미반영을 화면에 알린다

## 맥락

설정마다 효력이 생기는 시점이 다르다.

| 방식 | 언제 | 예 |
|---|---|---|
| 매 호출 조회 | 저장 즉시 | `sql_guard`, `chart`, 테이블 접근 제어 |
| 전역 캐시 + hot-reload | 설정 적용 | `rag`, `agent`, `audit`, 도구 등록, 그룹 권한 |
| 기동 시 1회 바인딩 | 재시작 | (현재 없음) |

문제는 방식이 여럿인 게 아니라 **어느 게 어느 쪽인지 아무 데도 적혀 있지 않다**는 것이었다.
설계 문서 §9 표가 유일한 기록이었는데 코드와 갈라져 있었다 — `tool_access`·`chart`·`estimator`
세 항목이 실제와 달랐다. 관리자는 저장하고 됐다고 생각하는데 반영이 안 되고,
개발자는 새 설정을 추가할 때 어느 방식을 따라야 할지 알 수 없었다.

실제로 이 때문에 반나절을 썼다. 차트 도구 권한을 해제했는데 반영되지 않아
버그로 의심했으나, 저장과 적용을 분리한 의도된 동작이었다.

## 선택지

### 옵션 A: 전부 hot-reload 로 통일

즉시 반영되는 것들에 캐시를 넣어 실제 동작까지 맞춘다. 선언과 동작이 일치하지만,
**잘 되던 걸 일부러 느리게 만드는 것**이다. 특히 `sql_guard` 는 SQL 차단 정책이라
즉시 반영이 안전한 쪽이고, 캐시가 늘면 같은 부류의 버그 표면도 늘어난다.

### 옵션 B: 선언만 통일 (전부 `RELOAD` 로 표기)

코드는 그대로 두고 관리자에게는 "저장하고 설정 적용" 하나만 알린다. 규칙이 단순해지지만
이미 반영된 것도 배너가 뜬다. 매번 뜨는 경고는 사람이 무시하게 되어 정작 필요할 때 안 본다.

### 옵션 C: 섹션별로 선언하고 화면이 읽는다

`ApiSection.apply_mode` 에 적고, `GET /settings/pending` 이 미반영 목록을 계산해 돌려준다.

## 결정

**옵션 C.**

- `ApplyMode`(`IMMEDIATE`/`RELOAD`/`RESTART`)를 `schemas.py` 의 `ApiSection` 에 선언한다.
  **config 가 아니라 코드에 둔다** — 관리자가 조정할 값이 아니라 구현이 정하는 값이고,
  어긋나면 화면이 거짓말을 하게 된다. 도구 카탈로그를 DB 로 옮기지 않은 것과 같은 기준이다.
- 판정은 서버가 한다. 프론트가 규칙표를 복제하면 문서 표가 그랬듯 반드시 갈라진다.
- 시각과 표식은 **프로세스 메모리**에만 둔다. 재기동하면 전부 반영된 상태이므로 초기화가 맞다.

판정 방식은 두 갈래다.

- **파일 섹션** — mtime 을 마지막 적용 시각(`RELOAD`)·기동 완료 시각(`RESTART`)과 비교
- **DB 설정** — 저장 API 가 `mark_db_changed()` 로 표식을 남기고 `hot_reload()` 가 지운다.
  권한을 전부 지우면 행이 사라져 `max(created_at)` 으로는 변경을 알 수 없기 때문이다.

기준 시각은 모듈 import 가 아니라 **기동 절차가 끝난 시점**(`mark_started()`)이다.
기동 중에도 설정 파일이 쓰인다(새 도구 시딩 표식을 붙이고 지우는 등).

추적 대상이 자의적이지 않다는 점이 중요하다. `hot_reload()` 가 다시 읽는 것 =
메모리에 캐싱하는 것 = 미반영이 생길 수 있는 것, 세 집합이 같다.

## 결과

- 관리자는 규칙을 외울 필요가 없다. 화면이 "무엇을, 어떤 버튼으로" 알려준다.
- 새 설정을 추가할 때 `apply_mode` 가 필수라 "이건 어느 방식이지"를 생각하게 된다.
- 라벨은 설정 화면 **섹션 헤더**와 같은 말을 쓴다. 하위 카드 이름을 쓰면 어디를 봐야 할지 알기 어렵다.
- 재시작이 필요하면 문구는 재시작 하나로 두고 목록에는 양쪽을 모두 담는다.
  재시작이 설정 적용의 상위 집합이라 관리자가 할 일이 하나로 정해진다.
- 선언과 실제가 어긋날 여지는 남는다. `RELOAD` 로 선언한 섹션이 실제로 `hot_reload()`
  단계에 있는지 검사하는 스크립트는 아직 없다.
