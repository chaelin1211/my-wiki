# ADR-043: 항목별 동작이 있는 커맨드 결과는 전용 컴포넌트로 보낸다

## 맥락

`/memories`는 메모리마다 삭제 버튼이 필요하다. 오픈소스 시절 구현은 메모리 1건당 카드 하나를 보냈는데, 웹은 카드를 "도구 결과"로 분류해 처리 과정 영역에 접고, 카드가 도착하면 앞선 텍스트까지 "도구 호출 과정"으로 확정해 내용이 흩어졌다. 또 웹은 새로고침 때 저장된 컴포넌트를 먼저 그리고 본문 텍스트를 뒤에 붙여서, 텍스트와 컴포넌트를 섞은 응답은 실시간과 새로고침 화면이 달라졌다.

## 선택지

### 옵션 A: 카드 유지
- **장점:** 기존 코드 그대로.
- **단점:** 처리 과정 영역에 접혀 보이지 않는다. 웹의 카드 분류 규칙을 바꾸면 도구 결과 카드 전체가 영향받는다.
- **비용/노력:** 없음.

### 옵션 B: 마크다운 텍스트 + 버튼 묶음 컴포넌트
- **장점:** 서버 변경만으로 가능.
- **단점:** 버튼이 항목 옆이 아니라 끝에 몰리고, 항목 사이에 끼우면 새로고침 때 버튼이 모두 뒤로 밀린다.
- **비용/노력:** 작음.

### 옵션 C: 마크다운 안의 특수 링크 (`[삭제](dna-cmd/<커맨드>)`)
- **장점:** 버튼이 텍스트 안에 있어 새로고침에도 위치 유지.
- **단점:** 링크 주소에 커맨드를 숨기는 우회라 직관적이지 않고, 스타일이 공통 마크다운 규칙에 묶인다(소제목 여백 변경이 LLM 답변에도 번짐).
- **비용/노력:** 작음.

### 옵션 D: 전용 목록 컴포넌트 (`item_list`)
- **장점:** 응답이 컴포넌트 하나라 텍스트와 섞이지 않아 새로고침 순서 문제가 없다. 항목 박스·버튼 위치·코드 블록을 자유롭게 그린다. 다른 커맨드 결과에도 재사용.
- **단점:** 백엔드 컴포넌트·저장 대상, 웹 타입·매핑·컴포넌트 추가가 필요.
- **비용/노력:** 중간.

## 결정

**옵션 D를 선택한다.** `item_list`는 제목·요약·구역(항목: 제목·보조 정보·코드·동작 버튼)을 담는 범용 컴포넌트다. 버튼은 동작 문장을 사용자가 입력한 것과 같이 전송하므로 커맨드 권한 판정·감사 로그가 그대로 적용된다.

## 근거

실제로 C를 먼저 구현했다가 사용자 피드백으로 D로 바꿨다. 새로고침 동작이 구조적으로 보장되는 것은 "응답을 한 덩어리로 보내는" D뿐이고, 공통 마크다운 스타일을 건드리지 않는다.

## 결과

- 백엔드: `src/dna/components/item_list.py`(DnA 전용 타입이라 직렬화 덮어씀), 컴포넌트 저장 대상에 `item_list` 추가. 텍스트 컴포넌트가 없는 커맨드 응답은 대화 본문을 비워 새로고침 때 중복 문장이 생기지 않게 했다.
- 웹: `components/item-list-block.tsx`, `flowKinds`에는 넣지 않아 본문 영역에 표시.
- `/help`의 예시 질문 버튼은 여전히 `button_group`이며, 웹이 버튼을 처리 과정 경계로 보지 않고 새로고침 때 본문 뒤에 두도록 보정했다. 필요하면 `item_list`나 단일 컴포넌트로 옮길 수 있다.
