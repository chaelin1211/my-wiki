# ADR-044: 북마크 페이지의 해제는 저장 전까지 보류한다

## 맥락

북마크 페이지는 해제한 카드를 화면에 남겨 두고 다시 누르면 재북마크되게 되어 있었다. 실제로는 해제 순간 서버에서 삭제하고, 다시 누르면 새 북마크를 만들었다. 그 결과 id·등록 시각·고정 상태가 새로 잡혀 고정 카드가 일반 목록으로 튀었다. 더 큰 문제로 `dashboard_widgets.bookmark_id`가 `ON DELETE CASCADE`라, 해제 순간 그 북마크를 쓰는 대시보드 위젯이 지워지고 재북마크해도 돌아오지 않았다.

## 선택지

### 옵션 A: 삭제 미루기 (클라이언트 대기 상태)
- **장점:** 되돌려도 고정·순서·제목·대시보드 위젯이 모두 그대로. 웹만 수정.
- **단점:** 저장 전에 페이지를 떠나는 경로를 모두 처리해야 함. 브라우저 뒤로 가기는 가로챌 수 없음.
- **비용/노력:** 중간.

### 옵션 B: 재등록 시 고정·시각 복원
- **장점:** 기존 즉시 삭제 흐름 유지.
- **단점:** 대시보드 위젯은 이미 연쇄 삭제되어 복구 불가. 서버 API 확장 필요.
- **비용/노력:** 중간.

### 옵션 C: 서버 보관 후 삭제 (`deleted_at`)
- **장점:** 기기·세션을 넘어 되돌리기 가능.
- **단점:** 스키마 변경과 모든 조회에 조건 추가.
- **비용/노력:** 큼.

## 결정

**옵션 A를 선택한다.**

- 해제는 서버 호출 없이 대기 상태로 표시하고, 다시 누르면 대기만 해제한다.
- 상단 막대에 대기 건수와 함께 삭제될 대시보드 위젯 수를 보여 주고, `저장`으로 한꺼번에 삭제, `되돌리기`로 전체 취소한다.
- 저장하지 않고 다른 화면으로 이동하면 `저장 후 이동`·`저장하지 않고 이동`·`취소`를 묻는다(이동 가드 `lib/leave-guard.ts`). 새로고침·탭 닫기는 브라우저 기본 확인창.
- 대기 중인 카드는 고정 버튼을 잠근다.

## 근거

위젯 연쇄 삭제까지 지키려면 "삭제가 일어나지 않은 상태"를 유지하는 것 말고는 방법이 없다. A는 그걸 가장 적은 비용으로 보장한다. 기기 간 되돌리기 요구가 생기면 C로 옮긴다.

## 결과

- 브라우저 뒤로 가기로 떠나면 저장하지 않은 해제는 버린다(북마크가 남는 안전한 쪽).
- 채팅 화면의 북마크 해제는 즉시 삭제를 유지하되, 대시보드에 포함된 북마크일 때만 확인창을 띄운다. 이를 위해 북마크 목록·참조 API에 `dashboards`(id·제목) 추가.
- 이동 가드는 레이아웃의 이동 핸들러와 사용자 메뉴(관리자·마이페이지·로그아웃)에 적용. 새 이동 경로를 만들면 `guardLeave`로 감싸야 한다.
