# ADR-042: 스킬 턴은 원문 저장 + 지시문 스냅샷, LLM 직전에만 블록으로 펼친다

## 맥락

`skill` 커맨드는 관리자가 등록한 지시문과 사용자가 커맨드 뒤에 쓴 입력을 함께 LLM에 전달한다. 무엇을 대화 이력에 저장하고 LLM에는 어떤 형태로 줄지 정해야 했다. 대화 제목(첫 사용자 메시지 앞 100자), 대화 검색(본문 정규식), 응답 취소 시 저장(요청 원문), 화면 표시가 모두 메시지 본문을 그대로 쓴다.

## 선택지

### 옵션 A: 본문에 펼친 블록을 저장
- **장점:** LLM에 줄 내용이 이력에 그대로 있다.
- **단점:** 제목이 지시문으로 시작하고, 검색 결과에 지시문이 보이고, 취소 저장본(원문)과 모양이 달라진다. 화면 표시용 원문을 따로 관리해야 한다.
- **비용/노력:** 중간.

### 옵션 B: 원문 저장 + 메타데이터 스냅샷, LLM 직전에 펼침
- **장점:** 제목·검색·취소·표시가 모두 원문으로 일관된다. 스킬을 고치거나 지워도 진행 중 대화 맥락이 바뀌지 않는다.
- **단점:** LLM 경로에 변환 필터가 필요하고, 요약·검색어처럼 원문을 읽는 다른 경로도 처리해야 한다.
- **비용/노력:** 중간.

### 옵션 C: 원문 저장, 지시문은 매번 DB에서 조회
- **장점:** 저장 데이터가 가장 작다.
- **단점:** 스킬 수정·삭제가 기존 대화 맥락을 바꾸거나 깨뜨린다.
- **비용/노력:** 작음.

## 결정

**옵션 B를 선택한다.**

- 사용자 메시지 본문은 입력 원문(`/monthly-sales 2026-08`), `metadata.command`에 이름·실행 방식·결과와 스킬 스냅샷(설명·지시문·사용자 입력)을 둔다.
- 대화 필터(`CommandHistoryFilter`)가 LLM 직전에 `<skill>` 블록으로 펼친다. 사용자 입력은 꺾쇠를 이스케이프하고, 지시문 우선 문장을 공통으로 앞에 붙인다.
- 이 필터는 필터 목록 **마지막**에 둔다. 턴 캡·존별 압축·대화 요약은 커맨드 턴도 한 턴으로 세야 요약 구간(`chunk_end`)과 어긋나지 않는다.
- 스킬이 아닌 커맨드 턴은 저장은 하되 LLM 맥락과 대화 요약에서 턴 단위로 뺀다.
- 대화 요약과 유사 질문 메모리 검색은 스킬 턴의 질문을 원문 대신 "설명 + 사용자 입력"으로 쓴다.

## 근거

본문을 읽는 기존 경로가 여럿이라 본문은 사람이 입력한 그대로 두는 편이 수정 범위가 작고 일관된다. 스냅샷은 대화 도중 관리자가 스킬을 바꿔도 이미 진행된 대화의 의미를 지킨다.

## 결과

- 코어 변경: `WorkflowResult`에 `message_metadata`·`history_response`·`llm_query`, `agent.py`가 LLM을 건너뛴 턴도 저장하고 `after_message` 훅을 실행.
- `ChatSaveHook`의 메타데이터 허용 목록에 커맨드 정보 추가.
- 응답 도중 취소하면 원문만 저장되고 스냅샷은 남지 않는다(다음 질문에서 지시문을 못 봄). 응답이 없던 턴이라 수용.
- 오래된 턴이 턴 캡에서 잘리면 스킬 지시문도 함께 빠진다. 일반 메시지와 같은 규칙.
