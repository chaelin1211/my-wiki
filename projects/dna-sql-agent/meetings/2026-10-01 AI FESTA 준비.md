## 준비 내용

### 진행 방식

- 설명을 먼저 하고 시연. 시연은 채팅 위주
- 후속 질문 프롬프트 확인 필요
- 시연 데이터: 행안부 주민등록 인구통계

### 설명 포인트 (논의 내용)

지식화 단계별로 무엇을 만드는지:

1. **관계도**
   - FK 우선 → 프로그램으로 관계 검색 → LLM 추론 순으로 관계를 찾음. LLM 추론으로 찾은 관계는 "추론 관계"로 표시
   - 네트워크 클러스터링 알고리즘(루뱅)으로 연관성이 높은 테이블끼리 그룹화
   - 그룹 이름은 LLM이 지음
2. **스키마 프로파일링**
   - 관계도 생성 후 테이블별 역할 판별 — 허브, 브릿지, 차일드, 룩업 등
3. **밸류 프로파일링**
   - 실제 데이터 값으로 검색할 수 있게 딕셔너리 생성 (라벨, 코드값, 컬럼 보유) → 질문을 기반으로 딕셔너리 검색
   - 예: "김포에서 출발~" 질문에서 '김포'가 공항 관리 테이블에 있는 값임을 찾아냄
   - 건수 제한이 있고 선별 기준은 커스터마이징 가능
4. **관계형 FAQ** — 관계를 바탕으로 예상 질문 생성
5. **SQL Example** — 가져온 기존 쿼리로 질문과 설명 생성

질문이 들어왔을 때 검색 흐름:

1. 사용자 질문 임베딩
2. 하이브리드 검색
3. 관계 추론 정보는 캐싱해서 인메모리로 유지 (성능 개선)
4. LLM 질의로 테이블 추출
5. Join path 알고리즘(MCS, 최소 연결 계산)으로 연관 테이블 추가 추출

## 예상 질문·답변 (러프)

세부 기술은 답하지 않는 걸 전제로, 개념 수준으로만 답변.

**제품 일반**

- **Q. 어떤 제품인가요?**
  A. 자연어로 질문하면 AI가 SQL을 만들어 DB를 조회하고, 결과를 표·차트로 보여주는 데이터 조회 에이전트. SQL을 몰라도 데이터를 바로 꺼내볼 수 있음.
- **Q. 일반 챗GPT에 SQL 짜달라고 하는 것과 뭐가 다른가요?**
  A. 챗GPT는 우리 DB 구조를 모름. 이 제품은 DB를 미리 분석해 테이블 관계·역할·실제 값까지 파악해 두고, 그걸 근거로 SQL을 만들고 직접 실행까지 함.
- **Q. 어떤 DB를 지원하나요?**
  A. Oracle, PostgreSQL, MySQL/MariaDB, Altibase 등 주요 관계형 DB 지원. 다른 DB는 요구에 따라 확장 가능.
- **Q. 어떤 LLM을 쓰나요?**
  A. 특정 모델에 묶여 있지 않음. 사내 구축형 LLM을 기본으로 쓰고, 환경에 맞게 다른 모델로 교체 가능.

**보안·도입**

- **Q. 데이터가 외부로 나가지 않나요?**
  A. 온프레미스(폐쇄망 포함)로 설치해 내부에서만 동작. 데이터가 외부 클라우드로 나가지 않음.
- **Q. AI가 데이터를 지우거나 바꿀 위험은요?**
  A. 조회(SELECT)만 허용하는 가드레일이 있어서 수정·삭제는 실행되지 않음. 민감 컬럼은 마스킹 가능.
- **Q. 사용자별로 볼 수 있는 데이터를 제한할 수 있나요?**
  A. 가능. 그룹·역할 단위로 접근할 수 있는 시스템과 기능을 관리자가 지정.
- **Q. 도입하려면 뭘 준비해야 하나요?**
  A. DB 접속 정보만 연결하면 지식화 과정을 거쳐 바로 질문 가능. 기존에 쓰던 SQL이 있으면 예제로 활용해 정확도를 높일 수 있음.

**기술 개념 (설명 포인트 연계)**

- **Q. 테이블이 수백 개면 AI가 어떻게 맞는 테이블을 찾나요?**
  A. 미리 DB 전체 관계도를 만들고 연관된 테이블끼리 그룹으로 묶어 둠. 질문이 들어오면 관련 테이블을 먼저 고르고, 연결에 필요한 테이블을 자동으로 보충함.
- **Q. FK가 없는 DB도 되나요?**
  A. 됨. FK가 없으면 컬럼 이름·데이터 패턴으로 관계를 찾고, 그래도 안 되면 AI가 추론함. 추론으로 찾은 관계는 따로 표시해서 구분.
- **Q. '김포'처럼 데이터 값으로 질문해도 알아듣나요?**
  A. 실제 데이터 값과 코드를 미리 사전처럼 정리해 둬서, 질문 속 단어가 어느 테이블·컬럼의 값인지 찾아냄.
- **Q. 사전 준비(학습)는 얼마나 걸리나요?**
  A. DB 규모에 따라 다름. 화면에서 지식화를 실행하면 단계별 진행 상황을 볼 수 있음. (구체 시간은 확답하지 않기)
- **Q. 정확도는 어느 정도인가요?**
  A. DB 구조와 데이터 품질에 따라 달라짐. 관계도·값 사전·SQL 예제를 쌓을수록 좋아지는 구조. (수치는 언급하지 않기)
- **Q. 틀린 SQL이 나오면 어떻게 하나요?**
  A. 생성된 SQL을 화면에서 그대로 확인할 수 있고, 실행 오류가 나면 AI가 스스로 고쳐 다시 시도함. 자주 쓰는 질문은 예제로 등록해 개선.

**결과 활용**

- **Q. 결과는 어떤 형태로 보나요?**
  A. 표와 차트(막대·선·지도 등)로 자동 시각화. 자주 보는 결과는 북마크하고 대시보드로 모아볼 수 있음.
- **Q. 이어서 질문할 수 있나요?**
  A. 대화 맥락을 유지해서 "그중 서울만", "작년이랑 비교" 같은 후속 질문 가능. 다음 질문 추천도 제공.
