# ADR-017: 관리자 설정 배너 — 전체 탭 기준 단일 저장 + 반영 방식 안내

## 맥락

관리자 설정 화면은 탭의 변경 점은 전역으로 보이고 탭 이동 제약도 없는데, 저장·리셋은 탭 단위였다.
"모든 변경사항 저장" 버튼조차 활성화 조건이 현재 탭 변경 건수라, 다른 탭에만 변경이 남으면 저장 버튼이
전부 꺼지고 탭의 작은 점만 단서로 남았다. 최초 구현(5/03)부터 같은 구조. 버튼도 5개로 많았다.

## 선택지

### 옵션 A: 현재 틀 유지, 활성화 조건·문구만 수정
- **단점:** 버튼 수·탭/전역 혼재 그대로

### 옵션 B: 저장과 적용을 합친 "저장 후 적용"
- **단점:** 백엔드에서 되살린 저장/적용 분리(ADR-046) 의미가 사라짐

### 옵션 C: 전체 탭 기준 단일 저장 + 적용은 분리 유지
- **장점:** 표시 단위와 저장 단위 일치, 버튼 4개

## 결정

**옵션 C를 선택한다.** 버튼은 `전체 저장` `설정 리셋` │ `설정 적용` `재시작`.

- 저장·리셋·미저장 건수 모두 전체 탭 기준
- 미저장 상태에서 반영 방식 안내: "※ 저장하면 바로 반영됩니다." / "※ [항목]은 저장 후 '설정 적용'(또는 '재시작')을 눌러야 반영됩니다."
- 판단: 파일 섹션은 `GET /api/v1/settings` 의 `apply_mode`, DB 권한 편집은 마스킹 그룹 액션·도구·화면정보 권한을 적용 대상, 마스킹 기본 액션·테이블 접근 제어를 즉시 반영으로 분류. 조회 실패 시 안내 생략
- 미저장·적용 대기 문구는 경고색, 완료 문구("모든 변경사항 저장·반영 완료" / "모든 변경사항 반영 완료")는 회색
- 한 섹션을 여러 카드가 나눠 쓰는 RAG 탭은 카드별 담당 필드만 비교해 변경 점 표시(`isDirtyAt`)

## 근거

- 탭 이동 시 편집을 유지(`forceMount`)하는 구조에서는 다른 탭 미저장 변경이 흔하므로 저장 단위가 전역이어야 함
- 적용 필요 여부를 저장 전에 알려야 "저장했는데 왜 안 바뀌지"를 줄임

## 결과

- 백엔드 ADR-046 과 함께 배포 필요
- 파운데이션·라이센스 탭은 배너 대신 안내 문구라 그 탭에서는 다른 탭 미저장 변경의 저장 버튼이 보이지 않음(후속 검토)
